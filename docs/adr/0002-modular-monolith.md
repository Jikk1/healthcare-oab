# 0002 — Модульный монолит на бэкенде

- Статус: Accepted
- Дата: 2026-06

## Контекст

Бэкенд обслуживает PHI (защищённые медданные) для мультитенантного SaaS: пациенты,
оценки риска, биллинг, аудит, аналитика. Команда — одна, продукт на ранней стадии.
Микросервисы дали бы изоляцию контекстов, но с операционным налогом (сетевые хопы,
распределённые транзакции, мульти-репо), который пока не оправдан.

## Решение

**Модульный монолит**: единый деплой, строгие внутренние границы модулей
`src/modules/<context>`. Каждый модуль владеет своим срезом схемы, сервисом и
роутами; межмодульные вызовы — через сервис-интерфейсы, а не через чужие таблицы.
Подробности — в [`backend/ARCHITECTURE.md`](../../backend/ARCHITECTURE.md).

## Последствия

- **+** Микросервис-подобное разделение ответственности без сетевого налога.
- **+** Границы уже прочерчены — контекст (движок риска, биллинг) можно выделить в
  сервис, когда понадобится независимое масштабирование/релизы.
- **−** Общий процесс/деплой: тяжёлый модуль влияет на остальные до выделения.
- Требует дисциплины: запрет на прямой доступ к таблицам чужого модуля.
