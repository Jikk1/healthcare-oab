# 0008 — Runtime-i18n: RU-источник + EN-словарь

- Статус: Accepted
- Дата: 2026-06

## Контекст

Продукт ориентирован на российских клиницистов (ФЗ-152, Приказ №965н), но публичным
маркетинговым/научным страницам нужна английская версия для международного охвата.
Полноценный фреймворк i18n избыточен; вводить `t(key)` во всю разметку — дорого и
ломает читаемость русского исходника.

## Решение

**Русский — источник прямо в разметке.** Переводимые узлы помечаются атрибутами:
`data-i18n="ключ"` (текст), `data-i18n-html="ключ"` (внутренняя разметка — заголовки,
пункты с маркерами) и `data-i18n-attr="attr:ключ"` (атрибуты, напр. placeholder).
EN-строки — в `locales/en.js` по ключам. `lib/i18n.js` при переключении меняет
`textContent`/`innerHTML`/атрибут, снимая снимок исходного RU в `WeakMap` для отката;
выбор языка хранится в `localStorage`, проставляется в `<html lang>`. Переключатель —
делегированная кнопка `[data-lang-toggle]`.

Покрытие переводом (на 2026-06): полностью — `index`, `cox`, `cox-demo`, `login`;
шапка+навигация — `predict`, `labs`. `dashboard` остаётся RU (внутренний кабинет для
RU-врачей, `noindex`). Юнит-тест `test/frontend/i18n.test.js` проверяет, что каждый
ключ в разметке есть в словаре и наоборот, плюс сам механизм подмены/отката.

## Последствия

- **+** Русский исходник читается как обычная разметка; нулевой рантайм при RU.
- **+** Расширение — механическое: разметить узлы + дополнить `en.js` (тест ловит расхождения).
- **−** Строки, генерируемые из JS (`innerHTML`-рендеры таблиц/результатов в
  `dashboard.js`/`predict.js`/`labs.js`), пока не локализованы — это отдельный
  workstream (нужно локализовать строковые литералы в JS, напр. через `t()`).
- **−** Значения `data-i18n-html` — доверенный контент из нашего словаря (не пользовательский), иначе был бы риск инъекции.
